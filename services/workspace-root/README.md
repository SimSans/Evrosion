# Native V5 Root controller

This separate executable consumes the actual selected V5 Root record (1104
bytes, 37 exact roles) and the readonly 12288-byte catalogue at pages 500..502.
It leaves the legacy Root supervisor executable unchanged. Kernel admission,
actual process identities, inherited capabilities and retained mappings remain
the authority boundary; catalogue IDs and packet fields are descriptive.

Root creates the 23 fixed channels in SDK order, delegates each exact child
shape, binds receivers and starts 11 independent processes. Both Editors use
one measured image and separate actual processes, controls, surfaces and File
windows. Actual38/59 observations supply identities. Negotiated 55 validates
the actual Job through retained ProcessCONTROL before setup-only JobCONTROL
closes; closing that handle does not free the Job, object or accounting.

Root alone retains the issuer for the protected 640x80 plane. It registers exact
actual producer identities, logical source/generation/epoch and geometry with
Display's Root-only receiver. A Display scene Commit completes before Root
queues Configure/Resize/Focus/full64-bit ScenePart low/high to each owner.
Per-owner bounded queues coalesce only wholly unsent desired scenes. An accepted
low half finishes with its matching high half; blocked Shell cannot consume
another owner's queue capacity or stop the independent Root UI.

`RECEIVE_EVENT39` supplies actual sender process/thread for Ready, raw physical
Input and application events. Root never accepts a packet PID as provenance.
It consumes raw relative PS/2 pointer events into 640x480 coordinates, routes
ordinary text/navigation to the focused actual owner and owns z-order, move
and resize. Ordinary accepted-view observations gate mouse widget routing.
Shell Window intents require a matching recent real forwarded Input gesture,
current model and actual Shell identity. The separately authenticated cursor
uses Display's own scanout and never reads runnable producer surfaces.
The latest application refusal retains that authenticated process/thread,
reason code, event count and Root observation tick in protected diagnostics;
duplicate display text is not treated as evidence of multiple events.

Inspector rows come from actual 38/42/55/Observe queries over a stated sample
interval, not an atomic machine total or CPU percentage. Root streams every
required 64-bit field half and commit nonce. Inspector displays only a fully
committed snapshot. An action must match a recent forwarded physical gesture,
the same accepted snapshot/model and actual Inspector sender. Refresh, paging,
window focus, layer views and compositor chrome preferences are implemented.
Privileged operations remain refused until their scoped control adapter joins.
The three views share the actual window/object model; selecting Layer3 grants
no authority and does not establish full-system Absolute Access.

The initial Root picker reads real namespace List/Inspect metadata through
the Root-only Workspace control receiver22. The exact Root two-page window at
503..504 serializes Namespace and binding traffic. Names use their actual full
UTF8 bytes, escaping unsupported font bytes so distinct names are not conflated.
An application Open intent only requests the chooser. Actual owner Input selects
an exact object, then a protected frame completes, followed by an actual Input
barrier. A later fresh Enter or released-button edge consumes the scoped witness.
Root rechecks current actor, object identity/revision/name and exact rights,
then obtains an actual Bind ACK and transfers the fixed scoped File SEND through
mechanism 44. Its finite 32-bit nonce is carried as the complete 8-byte request ID;
there is no truncation of a larger counter. READ ONLY never binds a writer.

Repeat Open and Save As now stage a correlated release, actual Kernel61 branch
retirement and authenticated Workspace reconciliation before a fresh binding.
Save As uses KeepDocument; readonly access never silently becomes a writer.
Private nonclone receipts derive only from actual61 Drained or an exact fresh
setup path that provably never delivered a SEND. An App ACK alone constructs
neither receipt. The full old lease/nonce/actual identity remains retained until
the service settles its exact known stage. One original finite cut covers the
transition; Busy does not renew it. Cancellation prevents the new binding while
finishing any release already accepted. Descriptor checks bracket Bind with
the full Entry and monotonic namespace revision before44. The protected body
shows actual E1/E2 process/thread, rights and full challenge nonce, including
explicit Save As overwrite intent. These are source/component changes; the
Root61/SaveAs native join still needs a new linked/VM checkpoint.

Any RootWorkspace RPC timeout, correlation/malformed response or
uncertainty permanently fences that physical window; no new packet or client
constructor resets it. Definite correlated Busy/Stale/Denied is distinct.

Package integrity/ABI/schema checks run before boot. After actual Workspace
Ready, Root issues the authenticated FileContract probe on its existing sole
control window before any App delegation. Loaded File2 minor/features are bound
to the actual held Workspace process/control/endpoint, epoch and measured image;
source constants do not advertise runtime support. New Editor requirements use
File2 minor1/STAGED_VERIFY, versioned BindContract and Selection2. Identity is
rechecked before binding and actual44 handoff. Old minor0 clients keep exact
Bind/Selection1 behavior; the original File1 readonly projection remains closed
and readonly. See ADR-0123. Fresh coherent SDK/negotiation VM acceptance remains
pending independently of host/native component checks.

Escape on the focused Saving Editor requests dedicated Cancel9002. The App
checks its actual precommit state, accepted presentation and original finite
cut before issuing one Abort. Other states keep the existing Root revoke flow,
and protected dialogs retain priority. This source routing and the App's host/
native preflights do not establish actual native cancellation acceptance.

Shell and Input recovery retain actual stopped Process controls through 55/fault
capture, bounded Reap, Close and denial checks. Fixed endpoints are reused only
after actual retirement. New actual processes receive fresh mapping/lifetime
epochs; old consent and held activation state cannot authorize a replacement.
Two bounded volatile diagnostic slots are retained in Root RAM, without a durable
export claim. Files/Editor lease or namespace recovery requires the separate
retirement/reconciliation joins. Block/NetDriver replacement is refused until
their actual device-stop protocol exists. Root exit is a retained terminal
boundary, not reusable cleanup or clean-shutdown evidence.

Normal startup uses one retained 8192-tick Ready bound per required service,
never renewed by progress. The explicit guest NEW-volume scan has not been
timing-qualified against it. A frontend-owned host NEW-volume format may qualify
normal-open graph debugging only when labeled as host provision; it does not
qualify guest provisioning or power-cut coverage. No ordinary Ready is invented.
