# Selected workspace frontend

Enable the additive host feature with `cargo run -p ev --features workspace --locked -- workspace --help`.

`packages` accepts measured Files, Editor and Inspector ELF paths and optional `--editor-candidate ELF`. Four actual Zion packages and `packages.json` record exact content identities and bank placements. A same-executable candidate can be inspected as a package, but V5 catalogue admission requires a distinct executable.

The selected Current bank holds 79 pages (323,584 bytes), while Candidate holds 63 pages (258,048 bytes). Each individual package still has the 63-page limit. Placements use the typed bank capacity, sixteen-byte alignment and exact nonoverlap checks. Full stack reports make the aggregate `bundle.json` larger than the separate build record: their finite reader limits are eight MiB and four MiB respectively.

The A1 snapshot/action/range boundary is the handwritten Internal SDK contract `ev.internal.semantic-tree@1`. Packaging an old ELF does not infer A1 support from its six-role resource shape. `packages` accepts explicit `--files-semantic-tree`, `--editor-semantic-tree`, `--inspector-semantic-tree` and `--editor-candidate-semantic-tree` declarations. Artifact JSON accepts a `semantic_tree` object with the same four boolean field names (without the flag suffix); absent fields are false. A declared package records the requirement from the SDK's shared version/feature constants and a digest over the exact `semantic.rs` and `semantic/operation.rs` source bytes. This producer declaration and source digest do not prove native consumption or authority. The source rebuild declares Editor A/B support; Files/Inspector require an explicit declaration once their implementations are qualified. The external probe sample does not declare A1 merely because it depends on the SDK.

`prepare --root PATH --output NEW_DIR --artifacts INPUT_JSON` requires schema 1, `workspace_mode` equal to `open` or `provision-new`, and named objects `root`, `shell`, `input`, `workspace`, `block`, `display`, `net_driver`, `net_service`, `files`, `editor`, `inspector`, and `editor_candidate`. Each object contains `path` and exact lowercase `sha256`. Relative input paths resolve against the JSON parent. Unknown and duplicate fields refuse. The Root/Display pair must implement the same local display-control protocol. The catalogue/manifest use the current typed V5 verifier, closed source policy and actual measured package placement.

An optional `file_app_packages` object supplies explicit `current` and `candidate` Zion inputs, each with `path` and `sha256`. Both corresponding ELF inputs remain mandatory. Their exact executable bytes must match the supplied packages, and the packages keep their actual external AppId, name, developer source, build, version, entrypoint and manifest bytes. The pair needs one distinct AppId, a newer candidate version, and different actual ELF/package/build identities. `Editor` names the closed FileApp6 resource slot in this catalogue; it does not relabel external software as the built-in Editor. This current public external profile has three explicit requirements and no inferred A1 declaration. Typed host preparation does not establish signatures, Root install policy or native execution.

`build` performs preparation and the selected Kernel/EFI build. `rebuild --root PATH --output NEW_DIR [--provision-new]` builds and snapshots every selected actor before the same producer/build path. Outputs are exclusive new directories. All native source builds use a shared explicit target and retain bytewise canonical-strip evidence; no source cleanup occurs.

`preview --root PATH --prepared DIR --headless --timeout 60 --host-provision-new` observes a normal-open bundle on a new owned disk. `--host-provision-new` is mandatory for that fresh-disk mode and forbidden for a guest NEW-only bundle. Explicit `--ovmf-code PATH --ovmf-vars PATH` override the pinned host defaults and fail rather than silently falling back. QEMU starts paused, validates the reviewed executable/source profile and private QMP state, then runs for a finite observation. Evidence distinguishes host provision, actual QEMU observation and still-open guest/runtime gates. No successful process exit or screenshot is labeled M8 acceptance.

See [ADR-0113](../../architecture/adr/ADR-0113-workspace-development-bundle-and-owned-preview.md). The frontend preserves the legacy commands.

The optional `--scenario files-basic` is fixed owned-VM integration automation. It requires `--host-provision-new` and at least 120 seconds, uses the actual logical 640x480 factory geometry, and sends bounded relative PS/2 packets and released key/button edges through the private QMP owner. It captures actual PNG scanout between characters and action phases. Before dependent input, it requires two matching status/name scanout samples at least 500ms apart; each visual wait stops after 10 seconds. This needs Python Pillow for read-only PNG decoding. The original host observation bound and guest RPC deadlines remain fixed. These visual checks only pace automation; the Root picker still requires its own presented challenge, input barrier, and a second distinct gesture. After the owned VM has exited, an OS read-only file handle opens the actual Dataset and checks `folder1` plus `note1` at a newer revision with exact bytes `hello workspace`. The input transcript and screenshots alone never count as a successful save or human approval. The complete source rebuild selects `workspace-profile` for both native network actors and separately compiles the real `update-b` Editor candidate.

`--scenario files-a1` retains that exact basic sequence and appends a fixed reader exercise. It requires at least 300 seconds and a compatible loaded Root/Inspector A1 pair. The extension observes READ-only filename access, a separate TEXT scope for the exact document, return to resource statistics after revocation, and an independently reviewed protected Root scope. It compares the visible dialog binding before and after ordinary protected Activate, then sends two released dedicated Confirm clicks separated by the actual changed challenge view. Every dependent action uses the same bounded screen gates through the existing sole QMP connection. Missing gates or an incomplete sequence stop the scenario; there is no input retry or second monitor. Pixel and binding-hash observations do not themselves prove protected authority, absence of data access, human approval, successful lease reconciliation, or completed accessibility qualification.

For a retained data fixture, normal-open `preview` accepts `--owned-data-template PATH --owned-data-template-sha256 HEX` instead of host provisioning. It requires an exact regular 96 MiB source opened read-only and creates a new owned output. Whole-file SHA, four/eight-MiB prefix hashes, inode and modification time are checked around the clone and after the VM exits. Neither the source nor the clone is formatted. The immutable prepared EFI/Kernel source identity and the current observer executable identity are recorded separately.

`--scenario large-io` requires that template mode and at least 120 seconds. A read-only preflight checks the exact dataset84/ns3/slot1/gen1/rev2 one-MiB ASCII fixture with first byte `a`. The scenario requests an actual RW selection, stops input unless initial exact loading reaches Saved, replaces only the first scalar with `Z`, then attempts Save and independent readback under the existing guest cuts. The first missing view ends input without a retry. Post-exit read-only inspection hashes every byte at the exact committed revision, distinguishes the baseline and edited patterns, and records retained stage/receipt metadata without repair. Cold integrity or publication does not imply the native client reached Saved.

The separate `large-io-finite` profile requires a 600-second maximum observation and a guest that implements the explicit finite whole-transfer policy. It keeps the same input sequence and permits finite Load/Save screen gates of 171,520 ms (the shared maximum allowance plus four RPC setup allowances). This host pacing allowance is neither a latency guarantee nor a renewal of any guest request. All other gates retain their 10-second bound; the pinned original `large-io` failure and its short gates remain unchanged.
