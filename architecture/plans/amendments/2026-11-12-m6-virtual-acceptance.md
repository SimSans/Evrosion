# M6 / 0.2 virtual acceptance amendment

**Authority:** explicit project-owner decision, 2026-11-12.
**Status:** accepted release-scope amendment; no runtime completion claim.

The owner nominated the current PC for development and has no spare machine.
After the distinction between virtual and physical acceptance was explained,
the owner explicitly selected: “Yes—VM-based 0.2; physical qualification later.”

Evrosion 0.2 is therefore a **VM-based Connected Developer Alpha**. M6-09 physical
qualification is deferred to a later milestone and is not a required dependency
of M6-10 / 0.2 acceptance. It is not marked PASS or represented by QEMU results.
The read-only host inventory may guide later work; it proves no Evrosion driver,
physical execution or device-retirement property.

Every virtual gate in [M6_PLAN.md](../../M6_PLAN.md) remains required: sustained
interactive operation and containment; reproducible target artifacts across the
declared build contexts; actual scoped NIC traffic and resource retirement;
time and entropy foundations; authenticated persisted executable admission;
healthy downloaded B promotion and bad C rollback to B offline with preserved
later edits; current negative/regression evidence and a fresh-environment guide.

No physical disk writes, host NIC assignment or physical boot are authorized by
this decision. Physical hardware qualification, safe owner-controlled installation
and broad computer support remain future product commitments. The original
owner-control, recovery, privacy/offline, resource and authority guarantees are
unchanged. A VM-qualified build must be described with that scope.
