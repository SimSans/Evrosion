# ADR-0113 — Measured workspace bundle and owned development preview

Status: accepted for the isolated M8 implementation; runtime qualification remains open.
Date: 2026-11-16.

The selected V5 graph needs a concrete build and packaging path under E-014. A generated descriptor, package declaration or host source inventory cannot establish actual device backing, service authority, consent, clean shutdown, or successful runtime admission. The existing frontend and prior release workflows remain available.

`tools/ev` provides an additive Cargo feature `workspace` and the explicit `workspace packages`, `prepare`, `build`, `rebuild`, and `preview` commands. Artifact JSON contains bounded regular ELF paths and exact lowercase SHA-256 values. Preparation copies the actual inputs, verifies every service through `ServiceImage::verify_m8`, derives role and instance digests from the selected Kernel helpers, audits the actual stack layouts, and produces the V5 catalogue and Root manifest through the typed producer and verifier. The fresh Authority identity calculation is a metadata dry run. Actual boot must independently realize and join every source identity and backing.

Files, Editor, Inspector and EditorCandidate are real self-contained Zion packages. Their entrypoints and descriptor resources contain the admitted ELF bytes and measured descriptor hash. The producer records the exact `ev.internal.workspace-ui@1` codec source hash and only parser-supported contract and capability declarations. Files' namespace route remains the fixed admitted seven-role Internal factory policy; a package declaration supplies no new authority. Package build identities derive from canonical package content. Actual package byte counts determine sixteen-byte-aligned placement in the separate Current and Candidate banks. [ADR-0117](ADR-0117-measured-current-package-bank.md) admits 79 pages for Current and retains 63 pages for Candidate; every individual package remains limited to 63 pages. The catalogue must reject overlap and mismatched placement lengths. A distinct version or package digest does not substitute for the catalogue's distinct candidate executable requirement. Boot packaging alone never qualifies signed dynamic updates, the generic installer, or intentional bad-candidate recovery.

The complete handwritten A1 snapshot/action/range codec has one Internal name, `ev.internal.semantic-tree@1`. Producer compatibility uses the public SDK's shared name, major, minor and feature constants. Each artifact declares A1 explicitly; absent declarations remain false so old measured ELFs do not acquire implementation claims from a matching resource shape. Declared packages retain a digest over the exact semantic and operation codec source files. This is not generated IDL or proof of native semantic consumption. Actual Root admission must independently check requirements against its loaded consumer before selected staging or authority changes.

The additive `ev app` workflow creates standalone projects against public SDK paths and retains measured build, package and verification evidence for a distinct claimed AppId. The closed selected-file-app resource shape is separate from built-in Editor identity. Its current sample uses generated File@2 and private RAM, without a durable App-private namespace. Install/run requests remain `NOT_APPLIED` until the signed Root factory, instance identity and owner policy path actually support that application. E-016's persistent data ownership and M8-11 remain open until a separate scoped namespace survives restart and denies foreign application access. Neither an ordinary Files-managed directory nor the sample's private RAM closes that obligation.

Source rebuilds select the actual M8 actor features, retain each full and canonical ELF, and compare every literal PT_LOAD byte, entry, and LOAD header before accepting `--strip-debug`. The selected Kernel build requires the real generated `EVROSION_WORKSPACE_BUNDLE` and feature `test-m8-workspace-run`; it does not supply stale V4 assets. The source inventory for the current producer and Kernel build is recorded separately from the owner receipts for prebuilt native ELFs. Source changes during the selected Kernel/EFI build refuse the build result. Stack reports retain unresolved paths and cycles; a resolved entry census is not a whole-program recursion or high-water proof.

The aggregate host bundle retains every full linked stack report and is bounded to eight MiB after the first A1 aggregate measured 4,477,315 bytes. The smaller build record remains bounded to four MiB. Both readers require regular JSON files and bound actual input reads. This evidence limit does not alter any guest stack, package, memory or deadline limit.

Preview creates an exclusive new 96 MiB disk, private writable OVMF variables, and an owned QEMU child. Its fixed ATA profile uses ISA ports 0x1e8/0x3ee; it never accepts an original data-volume path. Finite observation, serial-size bounds and a minimum two-GiB free-space guard constrain host work. The exact launch, emulator and firmware hashes, QMP exchanges, actual scanout capture and serial bytes are retained. Only the directly owned child may be terminated. Timeout or process exit is an observation result and supplies no clean-quiescence or recovery proof.

Two provisioning profiles remain distinct. The normal-open service never formats unknown storage. For first-graph debugging, the owner explicitly authorized `--host-provision-new`: the host invokes the actual `Dataset::format_new` on only the fresh workspace region beginning at sector 16384, using a finite host monotonic deadline. This newly created prefix is all zero; it is not a preserved historical Store or File volume. It verifies that the complete eight-MiB legacy prefix is unchanged and records that the initial dataset is empty. This is host provisioning, not guest provisioning throughput, target durability, or cut qualification. The separate NEW-only service profile must perform its own scan before Ready under the actual target envelope. The existing 8192-tick normal startup bound is not enlarged by the frontend.

The first executable graph and all subsequent receipts must name their actual compatible artifact pair and limitations. A retained physical runner owner, logical route revocation, or successful host codec test cannot be reported as normal service retirement, returned loans, flushed shutdown, accepted UI consent, or completed M8 qualification.
