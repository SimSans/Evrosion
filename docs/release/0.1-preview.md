# 0.1 Developer Preview scope

This is an early source snapshot of Evrosion's native architecture proof. It is
not a daily-driver OS, a physical-machine installer, a Stable SDK or an official
signed image release. See [source identity](../../SOURCE_IDENTITY.md) for the
publication candidate's exact validation state.

The accepted engineering line has executed native package lifecycle and retained
private data, selected-file READ grants and durable permission revocation,
App/Shell crash recovery, structured diagnostics and resource inspection,
provider replacement, and health-gated System recovery. Actual source, binary
and data identities matter; a status label or screenshot alone proves none of them.

## Runtime limits

- Controlled x86-64 UEFI/Q35/TCG, BSP userspace with parked APs and reference
  non-DMA devices. This does not qualify arbitrary PCs or general SMP/DMA.
- A bounded scripted demonstration rather than a sustained interactive desktop.
  Test input is explicitly scripted; it is not human usability or consent evidence.
- One fixed local owner/session. Production enrollment, authentication and a
  general secure-attention/Trusted Control product are not implemented.
- Source-built immutable package banks and bounded object/storage profiles.
  They are not a general filesystem, consumer package installer or online store.
- App/Shell replacement and selected-generation recovery are distinct from
  catastrophic loss of the common protected Root or Block driver. The latter is
  not automatically reconstructed by the current device-bearing Native workflow.
- Known Good requires actual declared health and admission. GUI readiness and
  Store creation provenance are not health receipts.
- Ordinary rollback/removal/reinstall preserve their declared separate data.
  General cross-build namespace compatibility, arbitrary migrations, hardware
  power-loss safety and every accepted in-flight revocation case are not implied.

## Validation and provenance

Historical acceptance applies to its exact measured inputs. A cleaned publication
snapshot has a different source identity and must retain its own build/test
results. Public technical editions and summaries are not byte-identical copies
of every original planning or evidence artifact. No historical PASS is silently
transferred by changing a document or source hash.

Exact artifact hashes remain authoritative. Local clean builds have matched,
while different host/toolchain/cache contexts can change full ELF metadata and
loader paths. This is not a hermetic or independent-third-party reproduction claim.
Generated artifacts and raw local run directories are not included merely by
pushing source files.

## Before running

Use disposable test data and the workflow-owned private disks. Do not boot the
fixture as a physical-machine installer or use it with irreplaceable files.
Review logs and captures before sharing them. Follow the [quickstart](../development/QUICKSTART.md).

Networking, sustained interaction and one nominated physical reference machine
belong to the next developer-alpha phase. Accessibility, owner sovereignty,
local operation, preservation-first installation and supported compatibility
remain product requirements; their broad implementations are not claimed here.
