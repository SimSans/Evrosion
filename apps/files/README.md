# Native Files

`ev-native-files` is the separate M8 Files executable. Its native path uses the
real namespace service through generated Workspace@1 frames, actual scalar RPC,
and its exclusively owned two-page window. Directory rows are loaded from the
Dataset; there is no compiled file catalogue or host-provided success path.
Host integration and actual bare linking do not establish guest acceptance.

The strict V1 startup is336 bytes with exactly seven ordered role shapes:
Surface Memory RW7, Present SEND8, RootEvents SEND8, RootControl RX|CONTROL272,
NamespaceFrame Memory RW7, GrantInbox RX|CONTROL272, Namespace SEND8. Limits are
the selected UI template `[16384,128,1,1]`. The safe app profile refuses aliases,
extra rights, wrong counts and limits without changing the old bootstrap ABI.
Native SelfIdentity59/INFO60 facts must match startup process and registered
incarnation. These descriptive facts never confer Root or content authority.

Root's independent sole-SEND control route sends SDK `ui::Command`. Configure
must select instance1 and a nonzero mapping epoch once; Ready1 acknowledges that
configuration. Ordered ScenePart low/high commands supply the entire64-bit
Root scene revision. Input is acted on only after configuration, focus, current
scene readiness and a usable surface. Resize changes bounded actual geometry;
the default is320x180 and the V5 maximum is320x200. The actual256-byte V5 header
and pixels occupy the separately admitted surface384..446. Present carries the
entire64-bit frame and requires an exact reply; MAX is an explicit completed
refusal. Any other failure retains/fences the surface, stops further interaction
and requires independent Root retirement. No protected Root plane is mapped.

The browser performs one real metadata RPC per load step: Inspect obtains the
current directory parent and namespace revision, then List returns at most eight
visible entries per page under that exact revision. Thirty-two bounded page
cursors cover256 entries. IDs retain full slot/generation, directory Up uses
actual metadata, and concurrent namespace revision changes refuse mixed lists.
List includes effective reversible trash state. New Folder and New Text create
actual directory/empty-file objects. Rename, metadata Move, Trash and atomic
Restore use the service's expected namespace revision. Move selects an object,
then lets the user enter a destination folder and apply; moving a trashed object
uses atomic restore-at. No purge/reclaim or File READ/EDIT is exposed.

The name field accepts valid UTF-8 scalars through96 bytes, scalar Backspace,
SelectAll replacement and Enter/Save to apply. Navigation keys cannot change
the target directory while name editing. The small bitmap font displays
non-ASCII scalars as `?`; exact UTF-8 bytes remain in names and namespace
operations. Names, scope IDs and a highlighted row never grant content access.
Opening a file emits Open to request Root's fresh protected picker; it does not
truncate an ObjectId into the eight-byte event or authorize a file by itself.

`apps/files::action` defines ordinary logical action IDs. Root owns actual
focus/input routing and must bind these actions to the accepted app view:

| IDs | Action and default logical area |
| --- | --- |
|1..5|Up, Folder, Text, Rename, Move; five equal columns, y0..19|
|6..10|Trash, Restore, Open, Prev, Next; same columns, y20..39|
|11,12|Apply, Cancel; rightmost120/60 pixels at y40..59 while editing/moving|
|13|Refresh after a definitive conflict or namespace change|
|100..107|Select actual visible row; y68+10×row|
|200..207|Enter selected row (directory navigation or trusted picker request)|

The separate SDK `namespace::{Client,Link,NativeLink}` allocates per-route
request/mutation nonces, retains exact original frames, checks finite original
deadlines and monotonic clocks, validates generated response correlation, and
pins the first successful DatasetId. NativeLink owns its actual mapping and
Namespace SEND, writes no packet identity, validates full64 scalar reply and
never returns loan credit from a timeout or malformed response. Accepted,
uncertain, corrupt or mutation-Stale outcomes retain the request and prevent
fresh IDs/window reuse. There is no public reset, retry, safe mapping constructor
or link extraction. Quiescent close consumes only the local handle and fences
further use even if close returns an unexpected failure; it does not unmap or
prove remote/device retirement.

Files permanently owns Frame506..507 for Namespace. Root must never publish a
Selection or install a competing Files File@2 lease while this session is active.
An unsolicited actual inbox capability is closed without reading Selection or
constructing a File client. Root's picker grants selected content to Editors
using their independently owned windows. Ordinary directory listing never
becomes blanket content authority.

Focused host tests run real Dataset+SectorIo+gateway+SDK+browser CRUD, renamed
stable IDs, move/trash/restore, cold actual names/parents, nineteen-entry paging,
UTF-8 name bounds, strict bootstrap and clipped pixels/hit tests. SDK adversarial
tests retain the same frame through malformed/wrong/remote/uncertain replies.
Actual V5 source grants, shared mappings, target timing, accepted view/input
binding, contention/death/recovery, accessibility and end-to-end VM qualification
remain separate M8 gates. The static stack census is not a runtime high-water
or whole-program proof. No Main or frozen source is changed by this component.
